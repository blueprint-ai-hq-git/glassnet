The model does not look the answer up: it writes the units column and its carry, then the tens column and its carry, then reads the hundreds digit off the final carry. Every number below is computed live in this page, in JavaScript, with no server.

Known weakness, measured: it scores 100.0% when the four unused input slots hold a fixed filler token and 75.3% when they hold varying filler — this app uses varying filler, so you may see it get one wrong. That gap is a real fragility, not a display bug, and it is the next thing being fixed.

This app holds no model

The app is the viewer and the runner. The model is a separate file you open — one app, any GlassNet model. Nothing here talks to the internet: the app is built with no network permission, so it cannot.
On a phone: tap Open model and pick a .glassnet file. On a computer: drag the file onto this page, or use Open model.

The final step, in full

The answer is chosen by a plain weighted sum — there is no hidden step: logits = u · AT, then take the largest.
These are the actual scores. The winner and the runner-up are shown with the gap between them, because "how sure" is a number, not a feeling.

Every neuron in the last layer, and what it contributed

The model's state is 64 numbers. The output weights squeeze them through just 4 rank dimensions before the answer, so the whole path from state to score is small enough to read.

Where it looked

Causal attention over the columns it has written so far. A column can only look backwards — that is enforced in the code, not requested in a prompt.

How it learned the pattern

Measured this morning: a checkpoint every 200 steps, scored on a benchmark fixed before training. It does not learn the pieces one at a time.
