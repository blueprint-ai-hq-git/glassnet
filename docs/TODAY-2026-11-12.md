# Today's work, 2026-11-12: the readable architecture, measured

One day on the phase-2 readable stack (Fashion-MNIST): 12 named concept neurons -> 32 sparse rules of 3 connections each ->
answer. Every number below came from a run today; every failure is listed with its number.

## Where it stands
```
readable stack, after rule pruning        81.73% +/- 0.54   (82.35 / 81.33 / 81.51, three seeds)
same weights before pruning               76.26% +/- 4.62
phase-1 plain baseline (no concepts)      86.69% +/- 0.59
connections per rule                      3.00 exactly (min 3, max 3)
rules a human must read                   27 / 26 / 21 of 32
concept honesty (rank agreement)          0.625 +/- 0.034; 2.3 of 12 concepts fit another name better
```
**The readable version is 4.96 points worse than the plain baseline.** That has not changed, and it is the headline.

## What actually improved it
1. **Linear rules instead of sigmoid rules: +5.09 points** (76.10 -> 81.19 at the same settings). The sigmoid version had
   saturated rules, so a concept feeding a saturated rule could not move the answer. The flag existed in the model and had never
   been exposed by the trainer, so that branch had never been trained.
2. **Deleting rules that cost nothing to delete: +4.48 +/- 1.52** (81.19 -> 81.73 with the variance floor). The removed rules were
   quietly harming borderline predictions, not merely inert.
3. **Honest concept names got cheap: 1.18 points at 32 rules**, against 3.68 points for the sigmoid stack and 9.88 for the
   concept-weight dial. Same halving of misnaming in each case.

## What is still broken, with numbers
- **A concept can mean exactly what its name says and decide nothing.** `top_heavy` reaches 0.968 rank agreement with its own
  label and switching it off changes **0.01%** of predictions; `ring_ink` 0.910 and **0.00%**. Minimum concept influence is
  0.00% in two of three seeds. Honesty is necessary for a readable model and demonstrably not sufficient.
- **Seven levers were tried against that defect.** Deleting the dead concepts cost 8.62 points; a weight-coverage penalty did
  nothing; dispersion-based concept selection did nothing; concept dropout cost 10.52; linear rules halved the count; coverage-aware
  pruning changed nothing (it preserved a rule worth exactly 0.000 points); a rule output-variance floor helped accuracy and left
  the minimum at 0.00%. The pattern: **every lever aimed at weights did nothing; the two aimed at behaviour both helped accuracy.**
  Weight magnitude is not a proxy for function at either level of this architecture.
- **Rules that share a concept triple are thresholds, not duplicates.** Collapsing them costs 26-47 points, so 29 rules is the
  honest reading count. This corrected an earlier claim of mine, published the same day.

## Method notes worth keeping
- Every arm is three seeds; a number without a spread is not reported here.
- Every tool prints the measurement that validates it before any other number (the audit reproduces the trainer's accuracy
  exactly, or it says MISMATCH).
- Every gradient change is checked numerically before use; the checks caught two of my own harness errors today.
- Stray numbers that look impossible (a rule worth 0.000 points) are kept in the record rather than tuned away.
